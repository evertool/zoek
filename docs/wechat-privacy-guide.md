# 微信《小程序用户隐私保护指引》整改记录 · 得闲开台

> 2026-09-18：审核驳回「《用户隐私保护指引》不明确或空白」的整改方案与当前状态。
> 结论：**只保留「收集你的昵称、头像」一项声明**；相册（Album）、剪切板（Clipboard）两项已从代码中彻底移除，
> 后台不再需要勾选。

## 1. 驳回原因复盘（关键教训）

驳回原文：

> 小程序存在《用户隐私保护指引》不明确或空白，请在小程序设置-基本设置-服务内容声明-用户隐私保护指引中清晰补充描述用户信息授权目的及信息收集场景，再提交代码审核。

后台那两格当时填的是「没有用相册、拍照、位置」「没有用剪贴板」——**这两项是平台按代码里的接口调用自动生成的**，
写「没用」= 与调用事实自相矛盾 → 判为「未清晰描述」。

⚠️ **重要：平台的接口识别是扫描代码，不是看有没有 UI 入口。**
`copyUserId()` 当时在 `profile.wxml` 里**根本没有任何绑定**（死方法），平台照样把它算作「读取你的剪切板」。
所以"不想声明某项"的正确做法只有一个：**把调用彻底删掉**，而不是删 UI / 不管它。

## 4. 删减声明的顺序（官方限制，容易踩）

微信官方《用户隐私保护指引填写说明》明确：

- 入口 1「账号设置 → 服务内容声明 → 用户隐私保护指引」→ 只影响**现网版本**；
- 入口 2「管理 → 版本管理 → 提交代码审核 → 信息填写页」→ 只影响**本次提审版本**，
  **提审被拦截时必须在这里改**；
- 「若当前提交审核版本**删除了**最新的线上版本隐私说明中包含的隐私接口，**无法在提审时进行编辑**，
  建议开发者在版本发布后通过**入口 1** 进行修改。」

因此本次建议这样走：

1. 入口 2 先尝试**取消勾选**相册 / 剪切板两项（界面允许就直接删干净）。
2. 若入口 2 不允许删减，则本次提审**保留**这两项，但把使用说明改为与当前版本一致的事实描述
   （例：「本版本未使用该能力，不会收集你选中的照片或视频信息」/「本版本不会读写你的剪贴板」），先让版本过审；
   **发布后立刻用入口 1 把这两项删掉**（此时代码已无调用，删完即与代码一致）。
3. 补充/修改声明约 **5 分钟生效**；提审表单里「是否采集用户隐私」**不要**勾「未采集」
   （否则会被回收隐私接口权限，报 `appid privacy api banned`）。

## 5. 提交前后自查

1. 真机跑一遍：选头像、改昵称、语音播报、记分 —— 确认弹微信隐私授权弹窗（平台兜底）、同意后功能正常；
   手帐页不再有「雀友合影留念」区块，我的页无复制入口。
2. 提审后若报 `errno 112 api scope is not declared`：说明某项漏声明（当前只可能是「昵称、头像」），回后台补勾。
3. 若下次审核要求**自适配**隐私弹窗（本项目未做，`app.json` 无 `__usePrivacyCheck__`；2023-10-17 后隐私功能默认启用、
   由官方弹窗兜底），需要：`app.json` 加 `"__usePrivacyCheck__": true` + `wx.getPrivacySetting` 判断
   `needAuthorization` + `<button open-type="agreePrivacyAuthorization">`（或 `wx.onNeedPrivacyAuthorization` 被动弹窗）。
   注意 `<input type="nickname">` 在用户未同意时会降级为普通输入框。需要时再加。
